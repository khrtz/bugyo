# Feature map

利用者から見た機能の地図です。変更を確かめるときは、該当する機能のファイルを**1つだけ**開いてください。全部読む必要はありません。

## 書き方
- 1機能＝1ファイル（`docs/features/<id>.md`）。`<id>` は `src/features/<id>` と同じ名前にする
- 先頭のfrontmatterに `id` と `spec` を書く。`spec` はその機能を実際に動かして確かめる `checks/<id>.ts`。`pnpm test` がspecの存在と対応漏れを検査する
- 本文は次の4つの見出しに答える。挙動のレベルで短く書き、ソースを読まなくても操作できるようにする
  1. **何があるか**
  2. **どう辿り着くか**（どの関数・どのコマンドから使うか）
  3. **どう操作して確かめるか**（`pnpm verify <id>` と、成功・エラー・空の各経路）
  4. **よく嘘をつくところ**（テストは通るのに使うと壊れている、が起きやすい点）
- 振る舞いを変えたら、同じ変更でこのファイルも直す
