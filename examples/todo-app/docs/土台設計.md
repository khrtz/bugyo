# 土台設計（要約）

## 構成
- src/app — ルーティングとProviderだけ
- src/features/<名前>/{ui,model,api,index.ts} — 外からは index.ts だけ
- src/shared/{ui,lib,api} — fetchは shared/api、useEffectは shared/lib だけ

境界は ESLint（no-restricted-imports / import-x/no-restricted-paths）と dependency-cruiser（.dependency-cruiser.cjs）の両方で強制。循環依存は dependency-cruiser の no-circular で検出する。

## 変更の種類ごとの完了条件

| 変更の種類 | 完了の証拠 |
| --- | --- |
| ドメインロジック（model/） | Vitestのユニットテストと、fast-checkによるプロパティテストが通る |
| バグ修正 | 修正前に「失敗するテスト」で再現し、修正後にそれが通る |
| UIの操作の流れ | 該当する流れをPlaywrightで実際に操作し、動画かトレースを添付する |
| UIの見た目 | Playwrightのスクリーンショット比較で、意図した差分だけが出ている |
| データの保存 | 保存した値を読み戻して一致を確かめる |
| 性能 | 変更前後の計測値（React Profiler、Lighthouseなど）を並べる |
| リファクタリング | 変更前に今の挙動をテストで記録し、変更後もそのまま通る |

## 新しいfeatureを足すとき
1. src/features/<名前>/ に ui・model・api・index.ts を作る
2. docs/features/<名前>.md を4つの見出しで書き、README の回帰の順番に足す。e2e/<名前>.spec.ts を書く（pnpm test が対応漏れを検出する）
3. pnpm check → pnpm verify <名前>
