# bugyo-mode

このプロジェクトは「エージェントが正しいやり方しか選べない」ように作られています。
禁止事項は lint と型が教えてくれるので、覚えておく必要はありません。
あなたの仕事は、作業の種類に合った進め方を選び、最後に**証拠**で完了を示すことです。

## まず確かめる

- `CLAUDE.md` を読む（コマンドと完了の定義が書いてある）
- 変更が触る機能を `docs/features/README.md` から探し、その機能のファイルを**1つだけ**開く。全部読まない。トークンは検証に使う

## 作業の種類を見分ける

| 依頼 | 進め方 |
| --- | --- |
| 新しい機能を足す | `bugyo new feature <id>` で雛形を作る → 画面に組み込む → `docs/features/<id>.md` を埋める。詳しくは `bugyo-new-feature` |
| バグを直す | **先に失敗するテストで再現**してから直す。再現できないうちは直さない |
| リファクタリング | 先に今の挙動をテストで固定し、変更後もそのまま通ることを示す |
| 仕組みを知りたい | `bugyo-explain` で実際のコードを辿って説明する。推測で答えない |
| レビューしてほしい | `bugyo-critique` で、証拠を先に見てから批判的にレビューする |
| 同じミスが2回目 | `bugyo-rule-from-mistake` でルールに変える |

## 書いている間

- **最小の修正を選ばない。** その場しのぎの修正は、次のエージェントがまねて広がります。正しい場所で、正しい形で直してください。根本原因が別の場所にあるなら、そこを直す
- lint に止められたら、エラー文の「代わりに何を使うか」に従う。`eslint-disable` で黙らせない。どうしても必要なら `-- 理由` を書き、ユーザーに伝える
- 既存コードがルールに反していたら、まねずに直す。違反を「例外リスト」に入れて残さない
- コメントで意図を説明しない（`noComments` を入れたプロジェクトでは lint が止める）。名前・型・テストで表す

## 完了の条件

`pnpm check` が通るだけでは完了ではありません。変更の種類ごとの証拠を出してから終わります。

| 変更の種類 | 出す証拠 |
| --- | --- |
| model/ のロジック | Vitest と fast-check のプロパティテストが通る |
| バグ修正 | 修正前に失敗し、修正後に通るテスト |
| UI の操作 | `pnpm verify <id>` が PASS し、`artifacts/` に動画・トレースがある |
| UI の見た目 | スクリーンショット比較で、意図した差分だけが出ている |
| リファクタリング | 変更前から通っていたテストが、変更後もそのまま通る |

報告では、何を変えたかの前に「どの証拠で確かめたか」を書く。確かめられなかったことは、確かめられなかったと書く。
UI を変えたなら、同じ変更で `docs/features/<id>.md` も直す（`pnpm test` が対応漏れを検出する）。
